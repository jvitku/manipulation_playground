# The Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app (FastAPI + vanilla JS) that teaches force-aware manipulation through 8 runnable lessons: live-controllable training, live charts, loss schematics, checkpoints, and parameterized policy evaluation with in-browser rollout viewers.

**Architecture:** A `lab/` package in this repo. Training/eval runs are subprocesses whose only contract with the server is the run directory (config/control/status/metrics/checkpoints as files). The FastAPI server lists tasks, spawns jobs, tails files; the SPA polls. Lessons reuse `src/fvb` (toy/contact2d/generative/nets/train, Stage-1 gantry pipeline, TD3).

**Tech Stack:** Python 3.11 (fvb-train image + fastapi/uvicorn), PyTorch, MuJoCo/robosuite (task 4+), vanilla JS + vendored uPlot, Docker compose service `lab` on 0.0.0.0:8430.

**Spec:** `docs/superpowers/specs/2026-10-22-lab-design.md`

## Global Constraints

- Branch `lab` of this repo; commit+push after every task (standing permission; never to `main`).
- Server binds `0.0.0.0`, port `8430` (owner connects remotely).
- Do not break existing `src/fvb` behaviour; extensions to it must be optional-arg only. `make test` (existing suite) must stay green.
- All Python runs inside the containers (`fvb:latest` CPU, `fvb-lab` for server/GPU jobs). Lab tests: `tests/lab/`, CPU-only, tiny configs, each file < 60 s.
- Run data under `lab/data/` (gitignored). Vendored JS under `lab/web/vendor/` (committed).
- Every lesson's numbers/claims come from `docs/FINDINGS.md`, `README.md`, `docs/stage2/matrix.md`, `docs/progress/journal.jsonl` — never invented.
- Every task page shows a runtime estimate from `lab/tasks/calib.json`; calibration constants are measured on this PC, never guessed.
- UI copy: plain English, no emoji, dark/light via CSS tokens.

## Review Focus

1. **Eval must rebuild the model from checkpoint metadata, not from the current form params** — a ckpt trained with H=16 evaluated while the form says H=8 must load and run (test in A3; repeated for every later task's `evaluate`).
2. **Partial-line reads of `metrics.jsonl` while the trainer appends** — the tail reader must skip an incomplete last line and pick it up next poll (test in A1).
3. **Server restart / browser re-attach during a long run** — `GET /api/runs/...?since=0` returns the full history and a live status for a subprocess the current server process did not spawn; stale PID in `status.json` (process gone, state still "running") is reported as `"failed"` with a message (tests in A1/A4).
4. **A crashing trainer (OOM, bad params) must end as `state="failed"` with the exception text in `status.json`**, never as a silently frozen "running" (test in A1: runner raises).
5. **Concurrent runs of one task must not clobber each other** — unique run ids, separate dirs, both listed (test in A4).

```python
# lab/core/runctx.py
class RunContext:
    def __init__(self, run_dir: Path): ...          # reads config.json -> self.params (dict), self.task_id
    def log(self, step: int, **series: float) -> None   # appends one JSON line {"step": step, **series} to metrics.jsonl
    def should_continue(self) -> bool    # polls control.json (<= every 0.5 s); blocks while {"cmd":"pause"} (status -> "paused"); returns False on {"cmd":"stop"}
    def save_ckpt(self, step: int, payload: dict, label: str | None = None, metrics: dict | None = None) -> Path
        # torch.save to ckpt/step_{step:08d}.pt, rewrites ckpt/last.pt, appends to ckpt/index.json: {"file","step","label","metrics","created"}
    def set_status(self, **kw) -> None   # merges into status.json: state, step, total_steps, wall_s, msg, pid, updated (iso)
    def done(self, msg: str = "") / fail(msg: str)      # terminal states "done"/"failed"

# lab/core/jobs.py
def start_job(kind: str, job_dir: Path) -> int          # spawns `python -m lab.run_job <kind> <job_dir>` detached (start_new_session=True), stdout/err -> job_dir/job.log, writes pid into status.json, returns pid
def read_status(job_dir: Path) -> dict                  # status.json + liveness: if state=="running"/"paused" and pid dead -> {"state":"failed","msg":"process died ..."}
def read_metrics(job_dir: Path, since: int = 0) -> list[dict]   # lines with 0-based line index >= since; skips a trailing partial line
def send_control(job_dir: Path, cmd: str) -> None       # cmd in {"run","pause","stop"}; atomic write (tmp+rename)
def new_job_dir(root: Path, task_id: str) -> Path       # root/<task_id>/<UTC yymmdd-HHMMSS>-<4 hex>; writes nothing else

# lab/run_job.py  (python -m lab.run_job {train|eval} <job_dir>)
#   looks up the task runner from lab.tasks.registry by config.json["task"], calls train(ctx)/evaluate(ctx),
#   wraps in try/except -> ctx.fail(traceback tail); ctx.done() if the runner returned normally without a terminal state.
```
