The question

Task 7 (vit-mnist) made tokens out of an image and let a summary token (CLS) collect whatever it needed; the question it answered was fixed ("which digit is this?"). Task 8 (cross-attn) showed a decoder asking questions of a separate memory. A robot policy needs both at once: it looks at a scene (image tokens) and is told what to do (a command token), and the command decides where in the scene to look. This is a vision-language-action model (VLA) in miniature, with the action replaced by the simplest grounded answer there is: where is the digit I was asked about — left, right, or not on the picture at all?

The task

Each sample is a 28×56 canvas: two MNIST digits of different classes side by side, and a query, a class from 0 to 9 ("find the 4"). The answer is left (0), right (1) or absent (2). A third of the samples are absent: the query is then drawn from the eight classes that are not on the canvas. Chance is therefore 33%, loss \(\ln 3 \approx 1.10\). Canvases are built fresh at every training step from the train_n digits (default 10 000 of the 60 000), so the model never sees the same pair twice, but the individual digits repeat. The validation numbers come from a fixed set of 2000 canvases built from the test digits, and absent accuracy is measured on its absent cases only. The loss is the cross-entropy of the three-way answer:

$$\mathcal{L} = -\log p_\theta(\text{answer}\mid\text{canvas},\ \text{query})$$

The method

The canvas is cut into 7×7 patches, a 4×8 grid of 32 tokens. As in task 7 each patch is flattened, linearly embedded and given a learned position vector, and depth self-attention blocks (minitf.Block) let the patches talk: a patch that is part of a "4" has to know it belongs to a 4 before anybody can ask for 4s. The query is a different kind of token. It is a learned embedding of the class (ten rows, one per digit), and it does not go through the blocks at all. It reads the patches through one cross-attention layer (minitf.MHA, the same module as in task 8, with the query token as \(x_q\) and the 32 patch tokens as \(x_{kv}\)):

$$\text{out}=\operatorname{softmax}\!\Big(\frac{(e_q W_Q)(X W_K)^{\top}}{\sqrt{d_k}}\Big)\,(X W_V)\,W_O,\qquad \text{logits}=W_h\,\operatorname{LN}(e_q+\text{out})$$

\(e_q\) is the query embedding, \(X\) the 32 patch tokens after the blocks and a LayerNorm. A head's attention row has exactly 32 weights and sums to 1: there is no CLS slot and the query is not among the keys. For the right answer the query has to find the matching patches (its \(W_Q e_q\) must score high against the keys of patches that look like that digit) and the values it brings back must carry where those patches are (the position vectors travel in \(X\)), or nothing at all if none matched. Nothing in the loss says "look at the digit": the model learns where to look because that is the only way to lower the loss.

The architecture

Shapes are for the defaults (2 blocks, 2 heads, d_model 64, 122 947 parameters). The query row of the attention is what the app draws: one 4×8 map per head over the canvas.

What to watch

While the run trains, the live attention panel under the charts shows a fixed probe canvas (the first two test digits of different classes) with the query set to the right digit. Each head gets one picture, tinted orange where the query attends (about 60 snapshots, each scaled to its own maximum). Early on the weights are spread evenly; later each head should pile onto the right half. After training, evaluate a checkpoint: the viewer steps through canvases (it cycles left, right, absent so every case shows up), shows the query, the truth, the prediction and its confidence, the attention of the head you pick, and, with the vector-grid toggle, the query vector next to the keys of the patches it attends to most.

Measured in this app (defaults: 2 blocks, 2 heads, d_model 64, 10 000 digits, 3000 steps, batch 128, lr 1e-3, GPU, 122 947 parameters; one run, seed 0):

  • Validation accuracy on the 2000 held-out canvases: 46.5% at step 200, 89.6% at 800, 94.3% at 1400, 95.6% at 2000 and 96.9% final; absent accuracy 61.3%, 84.8%, 92.5%, 95.9% and 98.3% on the same steps. The training loss goes from 1.26 (first logged step) to 0.020. 5000 steps instead of 3000 changed nothing useful (96.5% / 99.4% absent); the run takes about 64 s on a quiet GPU and up to 170 s when the box is busy.
  • On 5000 fresh canvases the same checkpoint scores 95.7% overall: 95.4% when the answer is left, 95.6% right, 96.3% absent. By query digit it ranges from 94.5% (query 2) to 98.1% (query 0). Its mean confidence is 98.2% when it is right and 81.8% when it is wrong.
  • Where the query looks: on canvases where the digit is present, head 0 puts 80% of its attention weight on the half that holds the digit (left 80.3%, right 80.9%) and head 1 73% (73.6%, 72.3%). When the digit is absent the weight is split evenly (50% and 51% in the left half): with nothing to find, the query reads everywhere. Averages of what a head does, not proof of how the answer is computed.
  • Other settings (one run each, same 2000 canvases): 1 block, 2 heads (72 963 parameters) reaches 95.7% (absent 95.6%); 2 blocks with 4 heads 96.7% (absent 97.8%); seed 1 of the defaults 97.4% (98.1%); learning rate 2e-3 97.8% (98.8%); 30 000 training digits 97.3% (97.2%). With only 2000 training digits it ends at 92.3% (absent 98.0%) with a training loss of 0.001: it memorises its digits, the same price of a small set as in task 7. The differences between the first ones are about the size of the seed-to-seed spread (96.9% against 97.4%), so read them as “all fine”, not as a ranking.
  • Noise the model never saw (Gaussian, std as a fraction of full scale, evaluation knob noise; same checkpoint, 5000 canvases): 95.7% at 0, 94.9% at 0.1, 89.8% at 0.2, 80.8% at 0.3 and 62.3% at 0.5, where the absent answer holds up best (82.7%) and left / right fall to 48% / 55%. Clean digits only were used in training.

Knobs

  • Transformer blocks and heads: depth is how much the patches get to talk before the query reads them; heads split the query's attention into parallel lookups (and each is a separate picture in the live panel).
  • Model width d_model, learning rate, steps, seed: the usual capacity and optimisation dials.
  • Training digits: how many distinct MNIST digits the canvases are built from; the canvases are new at every step, the digits are not.
  • Evaluation: query digit pins the question ("always ask for 7"; the examples then cycle left / right / absent for that digit), pixel noise corrupts the canvases, canvases to show sets how many examples the viewer gets.
