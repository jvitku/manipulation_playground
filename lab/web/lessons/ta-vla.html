The question

Can a transformer policy that already sees an image, a sentence and the robot state do better when it also feels? TA-VLA (Zhang et al., arXiv 2509.07962) answers by turning the recent force/torque history into one extra token and trains the policy to predict the forces its own action chunk will cause. This task is the miniature of that recipe: TAVLAMini (src/fvb/ta_tutorial/nets.py), a four-layer, two-stream transformer in the layout of pi0 and SmolVLA, trained from scratch on the contact scene of the earlier tasks — two holes, four commands (insert into the red hole, insert into the blue hole, press gently 2 N, press firmly 6 N). Everything is in the picture: the policy has to read the hole positions from a 32×32 image, read the command from words, and feel the surface through the torque token.

Motivation — why each technique is in this experiment

Two streams. The prefix (image, words, state) and the suffix (torque token + noisy actions) get separate weights so the two halves can be sized independently — and so a pretrained VLM can stand in as the prefix, as in pi0 and SmolVLA; the mini keeps the layout at trainable-from-scratch size.

The block mask and the KV cache. Prefix queries never see the suffix, so the prefix keys and values cannot depend on the noisy actions or on \(t\): encoded once per observation, reused for all K denoising steps — the design reason the two-stream layout pays at inference, and worth seeing in the mini where it is four lines of code.

The torque token. Force enters as a token because a token is the unit attention can select or ignore, per layer and head. Measured here: press gently (2 N) succeeds 98% with the token against 31% zeroed — a policy that cannot feel cannot tell 2 N from 6 N.

The auxiliary force loss. Predicting the forces the chunk will cause pushes the expert toward a small forward model of contact; at this scale the measured effect is small (−2 points in T3, +0.4 in T4), which is exactly why it is a knob (w) and not a default claim.

The zeroed twin. Same parameters, zeros in: the cleanest control for "what did force buy?", kept from task 5.

Theory — two streams, one mask, and force as a token

The two-stream layout is an inference-cost design. A VLA splits the work into understanding the observation (the prefix: image, words, state — the expensive part, a pretrained VLM in pi0 and SmolVLA) and writing the action chunk (the suffix — small, but run once per denoising step). The block mask is what makes the split pay: prefix queries never attend to the suffix, so the prefix's keys and values cannot depend on the noisy actions or on the noise level \(t\) — they are computed once per observation and cached, and each of the K denoising steps is one cheap pass of the expert, attending to

$$\operatorname{Attn}\big(Q_s,\;[K_p; K_s],\;[V_p; V_s]\big),$$

the cached prefix keys and values concatenated with the suffix's own. Separate weights per stream let the two halves be sized independently and a pretrained VLM be reused as the prefix.

Force enters as a token rather than numbers appended to the state for the same reason words and image patches do: a token is the unit attention can select or ignore, so every layer and head decides how much the torque history matters right now, instead of it competing inside one state vector. In the suffix (TA-VLA's choice) the token sits beside the actions being denoised and is re-read at every denoising step; in the prefix it is folded into the cache with the rest of the observation. The auxiliary loss \(L = L_\text{action} + w\,L_\text{torque}\) pushes further: predicting the forces the chunk will cause makes the expert's representation a small forward model of contact, not just a decoder of it — aimed exactly at commands whose success is defined in newtons, though the measured effect at this scale is small (below). The action head itself is flow matching: sampling integrates \(x \leftarrow x - \tfrac{1}{K}\, v_\theta(x, t, o)\) from noise to a chunk, which keeps multimodal demonstrations from being averaged.

The architecture

One attention sequence, two sets of weights. The prefix (image patches, words, state) runs through the “VLM” weights; the suffix (the torque token and the noisy action chunk) runs through the “action expert” weights. In every layer each stream computes its own queries, keys and values, but attention is joint and masked in blocks (right): prefix queries see only the prefix; suffix queries see the whole prefix and the whole suffix. Orange is the torque token; dashed is the auxiliary branch, present only when the weight w is above zero.

Prefix and suffix blocks: the action tokens attend to the prefix and to themselves
def prefix(self, xp):
    # B = batch, P = prefix tokens, D = width, h = heads, dh = D/h; xp [B, P, D]
    q, k, v = self.vlm.qkv_heads(xp)  # each [B, h, P, dh]
    # out [B, P, D]; (k, v) is this layer's KV-cache entry, each [B, h, P, dh]
    return self.vlm.finish(xp, F.scaled_dot_product_attention(q, k, v)), (k, v)

def suffix(self, xs, kv_prefix):
    # B = batch, S = suffix tokens, P = prefix tokens, D = width, h = heads, dh = D/h
    q, k, v = self.expert.qkv_heads(xs)  # xs [B, S, D] -> each [B, h, S, dh]
    kp, vp = kv_prefix  # cached prefix keys/values, each [B, h, P, dh]
    # the suffix attends to the prefix AND to itself (bidirectionally within the chunk)
    # keys/values cat along tokens: [B, h, P + S, dh]; attn out [B, h, S, dh]
    attn = F.scaled_dot_product_attention(q, torch.cat([kp, k], 2), torch.cat([vp, v], 2))
    return self.expert.finish(xs, attn)  # [B, h, S, dh] -> [B, S, D]
The torque token joins the suffix next to the noisy action tokens
def torque_token(self, cond):
    # B = batch, D = width, Tq = flattened torque-history dims; cond["torque"] [B, Tq]
    tq = cond["torque"]  # [B, Tq]
    if self.zero_torque:
        tq = torch.zeros_like(tq)  # the zeroed twin: same parameters, no signal
    return self.torque_mlp(tq)[:, None, :]  # [B, Tq] -> [B, D] -> one token [B, 1, D]

def forward(self, x_t, t, cond):
    # B = batch, H = chunk horizon, A = action dims, D = width, S = suffix tokens, F = aux dims
    kvs = self._kv if self._kv is not None else self.encode_prefix(cond)  # prefix kv per layer
    a = self.action_in(x_t)  # [B, H, A] -> [B, H, D]
    te = time_embedding(t, self.d)[:, None, :].expand(-1, self.horizon, -1)  # [B] -> [B, H, D]
    s = self.action_time(torch.cat([a, te], dim=-1)) + self.act_pos  # [B, H, 2*D] -> [B, H, D]
    if self.torque_pos == "suffix":
        # prepend the torque token: [B, H, D] -> [B, S, D] with S = 1 + H (else S = H)
        s = torch.cat([self.torque_token(cond).expand(s.shape[0], -1, -1), s], dim=1)
    for blk, kv in zip(self.blocks, kvs, strict=True):
        s = blk.suffix(s, kv)  # [B, S, D] -> [B, S, D]
    h = self.ln_out(s[:, -self.horizon :])  # the action tokens: [B, S, D] -> [B, H, D]
    # aux head: h.mean(1) [B, H, D] -> [B, D] -> future-torque prediction [B, F]
    extra = {"aux": self.aux_head(h.mean(1))} if self.aux_head is not None else {}
    return self.action_out(h), extra  # velocity [B, H, D] -> [B, H, A]

Why the block mask matters: the KV cache

Because the prefix never looks at the noisy actions, its keys and values do not depend on the denoising step. At run time the policy encodes the prefix once per observation (with model.cache(cond): ...), stores the keys and values of every layer, and reuses them for all K flow-matching steps; only the cheap suffix is recomputed K times. Each denoising step is one pass of the action expert over 9 tokens that attend to the cached prefix. (The image is rendered from the 5-number scene state inside the prefix encoder, so the training set stores numbers, not pixels, and the camera is simulated.)

The ladder's punchline: self vs cross is a mask pattern, not machinery. Tasks 6–9 wired one operation three ways: a lone query reading a set of stored pairs (task 6), a sequence talking to itself (self-attention, task 7), one stream reading another (cross-attention, named in task 8, used as an interface in task 9 and by task 5's learned queries). TAVLAMini retires the distinction: it has no separate cross-attention module, just one softmax over \([K_p; K_s]\) with a block mask. Inside that one softmax the prefix quadrant is self-attention (the observation talks to itself) and the suffix-reads-prefix quadrant is cross-attention (the action expert reads the observation) — the same operation, told apart only by who is allowed to see whom. One operation, three wirings, and a mask can express every one of them.

Two losses

The action tokens are trained exactly like the earlier flow tasks. With \(x_t = t\,e + (1-t)\,x_0\) a noisy chunk, \(\hat v\) the expert's output and \(m\) the mask of real (not padded) chunk positions, $$L_\text{action} = \frac{\sum m\,\lVert \hat v_\theta(x_t, t, o) - (e - x_0) \rVert^2}{\sum m}.$$ The second loss is TA-VLA's: a linear auxiliary head reads the mean of the expert's action-token outputs and must predict the next 8 force readings that the demonstration produced (F, z-scored), so the expert's representation has to model the contact forces the chunk will cause: $$L = L_\text{action} + w\;L_\text{torque},\qquad L_\text{torque} = \lVert \hat F_{i+1:i+8} - F_{i+1:i+8} \rVert^2 / 16.$$ The weight is the Aux weight knob (0 removes the head; 0.1 in the repository's experiments). The aux-MSE chart shows \(L_\text{torque}\) itself, not the weighted term.

Where does the torque token go?

  • suffix (decoder; TA-VLA's choice): the token sits next to the actions being denoised, so every step of the expert can read it directly. Its keys are in the suffix, so the prefix cache is unchanged.
  • prefix (encoder): the token joins the observation; it is cached with it and the actions see it through the prefix keys.
  • none: no token (no force). Zero the torque input keeps the token and its weights but feeds zeros: the “blind twin”, the cleanest ablation, because the parameter count is identical.

The paper found the decoder placement better. This repository measured it at small scale (below) and could not reproduce a gap there.

What this repository measured (and where it did not hold)

These are the repository's own results (docs/ta_tutorial.md, docs/FINDINGS.md), quoted with their setups:

  • T3, peg search with unknown surface (400 demos, 3 seeds): torque token zeroed / prefix / suffix / suffix + aux = 61.3 / 85.5 / 86.7 / 84.3 %. Force is the difference between guessing and knowing when the peg has touched down; without it the failures are mostly force aborts.
  • T4, this task's world (four commands, 1 600 demos, 2 seeds, 400 evaluation episodes each): zeroed / prefix / suffix / suffix + aux = 62.9 / 91.3 / 91.4 / 91.8 %. The sharpest row is press gently (2 N): 98 % with the token against 31 % zeroed; the insertion commands are equal (96–97 %). A policy that cannot feel cannot tell 2 N from 6 N.
  • Position and aux at this scale: prefix ≈ suffix within seed noise, and the auxiliary loss did not help (−2 points in T3, +0.4 in T4). The paper's decoder advantage is not reproduced here.

The honest counterpoint. With the real model the sign flipped. In the SmolVLA (450M) insertion experiments, 100 held-out set-ups per arm, the torque token fed real force hurt: raw token 53 % and 48 % (two seeds) against the zeroed twin 66 % and 61 %; pooled 101/200 vs 127/200, Fisher p = 0.011. The same 158 demonstrations let a small MLP gain from force (28.8 vs 6.8 %), so the signal was there; the working hypothesis is that the large model latches onto the torque history as a shortcut. The auxiliary loss (w = 0.1) did not repair it (50 %). So the lesson is not “force tokens help”: they help a small model on a task where force carries the missing information, and they were harmful in a large model with few demonstrations. Measure the zeroed twin every time.

Running it

  • The default (800 demos, 15 000 steps, width 128, about four minutes on a GPU) reaches roughly 95 % on the two presses but only around 50–60 % on the insertions: localising a 1.2 cm hole from a 32×32 image (one pixel is 1 cm) is the hard part and wants data. The tutorial's reference runs used 1 600 demos and 30 000 steps and reached 91 % overall; raise Demonstrations and Training steps to approach that, or use width 64 and fewer steps for a quick look. A closed-loop evaluation on 200 fixed scenes runs every Eval every steps and feeds the success per command chart: watch press gently and press firmly separately from the two insertions.
  • Train two runs that differ in one knob: position suffix vs prefix, or Zero the torque input on/off, or w = 0 vs 0.1. One run is one seed; a few points of difference is seed noise at this size, so read the 95 % interval in the viewer table.
  • Blind at evaluation takes a checkpoint trained with force and zeroes the token input only while testing. If its press-gently success collapses toward chance while the insertions barely move, the policy was really using the force, which is what the viewer's “force input” chip reports. A checkpoint trained with zeroed input shows the chip already.
  • The viewer lists outcomes per command, then replays rollouts in the side view with the red and blue holes (a box marks the commanded hole) and the force window; the policy has no hole-position input other than the image.
