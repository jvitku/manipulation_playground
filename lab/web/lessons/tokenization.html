The question

A transformer eats token ids and emits a distribution over token ids. Text fits that interface naturally; a robot action is two floating-point numbers. So how does an action get in and out? Three interfaces are in actual use: keep it continuous (regress floats, as task 1 (bc-mse) did, or sample them with a generative head, as task 2 (flow) did), chop each dimension into bins and classify (one independent softmax per dimension), or write the action as a token sequence and let the model spell it out one token at a time, exactly like a sentence. This task trains all three on one tiny problem built so that they come apart — same trunk, same data, only the interface changes.

The task

The diagonal two-mode problem. The observation is one number \(c \sim U(-0.4,\, 0.4)\). The expert flips a coin \(s = \pm 1\) and acts

$$a^\ast = \bigl(c + s\,g,\;\; 0.5 + s\,h\bigr) + \mathcal{N}(0,\, 0.05^2), \qquad g = 0.5,\; h = 0.25,$$

so the two modes are \((c - 0.5,\, 0.25)\) and \((c + 0.5,\, 0.75)\). It is the same family as task 1 (bc-mse) and task 2 (flow) — an obstacle at \(\lvert a_x - c \rvert \lt 0.25\), pass it left or right — with one twist: both action dimensions flip together. The x choice and the z choice are correlated through \(s\), and that correlation is exactly the property that separates the three heads below. A pair that mixes the sides (left x with right z) matches no expert mode. Actions already live in \([-1, 1]\) (x in \([-0.9, 0.9]\), z in \(\{0.25, 0.75\}\)), so nothing is z-scored here: the uniform quantisation grid over \([-1, 1]\) is the normalisation.

The method

Continuous regression (head cont). An MLP maps \(c\) straight to two floats and trains with

$$L = \lVert \hat a - a^\ast \rVert^2 .$$

The L2-optimal prediction is the conditional mean \(\mathbb{E}[a^\ast \mid c] = (c,\, 0.5)\) — the centre of the obstacle. Task 1 (bc-mse) made this failure the whole lesson; here it is the baseline.

Per-dimension bins (head bins). Each action dimension is clipped to \([-1, 1]\) and quantised into \(K\) uniform bins (\(K\) = Bins per dimension),

$$q(a) = \Bigl\lfloor \tfrac{a + 1}{2}\, K \Bigr\rfloor ,$$

and the same trunk now ends in \(2K\) logits — a \(K\)-way classification per dimension, trained with cross-entropy against the expert's bin indices. Classification has no reason to average: each marginal becomes cleanly bimodal. Decoding samples a softmax per dimension and returns the bin centre. This is the RT-1 recipe (256 uniform bins per action dimension). But the two softmaxes are independent: the head models

$$P(t_x \mid c)\, P(t_z \mid c),$$

the product of the marginals, not the joint — and in this problem the joint is the point.

Autoregressive tokens (head ar). The action becomes a 2-token sequence over a vocabulary of \(K\) ids, and a tiny causal transformer factorises the joint by the chain rule:

$$P(t_x, t_z \mid c) = P(t_x \mid c)\; P(t_z \mid c,\, t_x).$$

The observation enters as a projected obs token, each action token is a row of an nn.Embedding table, and decoding samples \(t_x\) first, then feeds it back in and samples \(t_z\) given \(t_x\) — the same mechanism that lets a language model keep a sentence coherent token by token, and the style of RT-2, where actions are literally emitted as text tokens by a VLM.

This is the same id-lookup machinery as text tokenization: characters, words or byte-pair merges become integer ids, and an id is nothing but a row index into an embedding table. Task 8 (cross-attn) reads dates with exactly this interface — a 39-token vocabulary (36 characters plus pad/bos/eos) — and the evaluation ships that character vocabulary, so the playground (section a of the viewer) lets you tokenize “23 Oct 2026” and the two actions with the same moves.

Motivation — why each technique is in this experiment

The diagonal variant. In task 1's problem one bimodal dimension was enough to break regression; here both dimensions flip together through \(s\), because correlation is the one property that also separates the two token heads — marginals suffice for independent dims, only a joint model keeps correlated ones paired.

Three heads in one run. Same trunk (the bins head is literally the cont MLP with a wider last layer), same data stream, same Adam, steps and batch, fresh seed per head: a controlled comparison in which the action interface is the only variable.

Uniform bins. The actions already live in \([-1, 1]\), so the uniform grid doubles as the normalisation (nothing is z-scored), and it is the RT-1 recipe in miniature — 256 bins scaled down to 9/17/33.

The temperature knob. Multimodality lives in the sampling: temperature ≤ 0.01 decodes argmax and every draw collapses to one pair, which you can watch happen in the scatter.

The probe at c = 0. The raw softmax probabilities at one observation, no temperature: the distributions the heads actually hold — two independent marginals for bins, and an AR \(P(t_z \mid c,\, t_x)\) that visibly flips when you feed it the other \(t_x\).

A text playground in an action task. The AR head’s machinery — ids as embedding rows, the chain rule — is exactly text tokenization, so the evaluation ships task 8’s character vocabulary to show the same moves on a date string.

Theory — why tokenize at all, and what the factorisation buys

Tokenising an action buys the entire language-model toolchain. A softmax over ids gives an exact, normalised likelihood for any discrete joint via the chain rule,

$$P(t_1, \dots, t_n \mid c) = \prod_{i} P(t_i \mid c,\, t_{\lt i}),$$

trainable with plain cross-entropy (no mode averaging, however multimodal the target), and sampling from it gives multimodality for free — plus temperature, argmax and beam search as knobs. The catch is the factorisation you pick. Per-dimension bins model only the marginals, \(P(t_x \mid c)\,P(t_z \mid c)\): fine when dimensions are independent, wrong the moment they correlate. The autoregressive factorisation is exact for any joint; the token order changes only how easy each conditional is to learn. The price of tokens is quantisation error (a bin centre is off by up to half a bin) and sequence length — real action chunks at 50 Hz make naive binning hundreds of highly correlated tokens.

Text made the same moves first: characters are exact but long, words are short but unbounded, BPE interpolates by greedily merging frequent pairs — a bigger vocabulary buys shorter sequences at the cost of a larger embedding table and rarer, worse-trained rows. The modern robot-action spectrum spans the same trade: RT-1 uses 256 uniform bins per dimension (our bins head, scaled up); RT-2 spells actions in the VLM's own text tokens; FAST DCT-transforms the action chunk and BPE-compresses the quantised coefficients, cutting the token count by an order of magnitude; and pi0 / SmolVLA skip tokens for the action side entirely and keep a continuous flow head — task 2 (flow)'s answer, attached to a VLM.

The architecture

One observation, three heads, trained one after another with fresh seeds. The dashed path carries the expert action into every loss: raw floats for the MSE, quantised token ids \(t^\ast_x, t^\ast_z\) for both cross-entropies. The ar lane trains teacher-forced (the expert's \(t^\ast_x\) is fed in) and decodes with its own sampled \(t_x\) — the dashed feedback loop.

The grid: edges, centers, and quantisation into token ids
def bin_edges(n_bins: int) -> np.ndarray:
    return np.linspace(-1.0, 1.0, n_bins + 1)


def bin_centers(n_bins: int) -> np.ndarray:
    e = bin_edges(n_bins)
    return (e[:-1] + e[1:]) / 2


def quantize(a: torch.Tensor, n_bins: int) -> torch.Tensor:
    """[-1, 1] values (clipped first) -> bin indices, same shape, int64."""
    return (((a.clamp(-1, 1) + 1) / 2) * n_bins).long().clamp(0, n_bins - 1)
The two cross-entropy losses: independent bins vs teacher-forced tokens
def _loss_bins(model, c, a, n_bins):
    logits = model(c).view(-1, 2, n_bins)
    tok = quantize(a, n_bins)
    return (F.cross_entropy(logits[:, 0], tok[:, 0]) + F.cross_entropy(logits[:, 1], tok[:, 1])) / 2


def _loss_ar(model, c, a, n_bins):
    tok = quantize(a, n_bins)
    logits = model(c, tok[:, 0])  # [B, 2, n_bins]
    return (F.cross_entropy(logits[:, 0], tok[:, 0]) + F.cross_entropy(logits[:, 1], tok[:, 1])) / 2
Decoding: sample the dims apart (bins) vs t_z given t_x (ar)
@torch.no_grad()
def bins_sample(model, c, n_bins, temperature, gen):
    """Per-dim independent softmax sample -> token ids tx, tz [B]."""
    logits = model(c).view(-1, 2, n_bins)
    return _pick(logits[:, 0], temperature, gen), _pick(logits[:, 1], temperature, gen)


@torch.no_grad()
def ar_sample(model, c, n_bins, temperature, gen):
    """tok_x from P(.|c), then tok_z from P(.|c, tok_x) -> token ids tx, tz [B]."""
    tx = _pick(model(c)[:, 0], temperature, gen)
    tz = _pick(model(c, tx)[:, 1], temperature, gen)
    return tx, tz
The AR head: obs token + token embedding into a 2-block causal transformer
class ARTokenHead(nn.Module):
    """Tiny causal transformer over [obs-token, tok_x]; logits [B, T, n_bins] per position."""
    # ...
    def forward(self, c: torch.Tensor, tok_x: torch.Tensor | None = None) -> torch.Tensor:
        x = self.obs(c)[:, None]  # [B, 1, D]
        if tok_x is not None:
            x = torch.cat([x, self.emb(tok_x)[:, None]], 1)  # [B, 2, D]
        x = x + self.pos(torch.arange(x.shape[1], device=x.device))
        mask = causal_mask(x.shape[1]).to(x.device)
        for b in self.blocks:
            x, _ = b(x, mask)
        return self.head(self.ln_f(x))

What to watch

Numbers below are from a small reference run of this task (800 steps per head, 9 bins, d_model 16, temperature 1.0, on CPU) — your run at the defaults should tell the same story with its own values. In the outcome table: the cont head put 100% of its samples in the obstacle (collision 1.000, mode error 0.514) — the conditional mean, sitting dead centre between the modes. Its pairing column read 1.0, and that is not a win: with both residuals a hair from zero, sign(dx) == sign(dz) compares the signs of sub-noise leftovers of one deterministic function — a degenerate artifact, not valid behaviour. The bins head fixed the collision (0.002) but its pairing was a coin flip: pair_valid 0.510. The ar head got both: collision 0.003, pair_valid 0.996, mode error 0.109.

The probe scatter (samples at one obstacle position) draws the mechanism: cont is a single blob in the middle, bins fills all four corners — each marginal is bimodal, but x and z are drawn independently, so half the pairs mix the sides — and ar keeps only the two valid corners. Then open the playground's section d: in the reference run the AR x-distribution at \(c = 0\) peaked at bins 2 and 6 (centers \(\pm 0.444\), the quantised \(\pm 0.5\) modes), and clicking the two buttons flips \(P(t_z \mid c, t_x)\) from a peak at bin 5 (center \(+0.222\), the low mode) to bin 7 (center \(+0.667\), the high mode) — the second token literally reads the first. Section e shows the token-embedding table as a vector grid: a token id is nothing but a row index into it, with the expert example's two tokens marked.

Knobs

  • Training steps per head (default 3000): each of the three heads trains this many Adam steps, so a run costs about three single trainings. The AR head is the slowest to sharpen; the loss chart overlays all three (log scale — MSE and CE are different units, read trends, not levels).
  • Learning rate (1e-3) and Batch size (256): shared by all heads; mostly speed and noise knobs.
  • Bins per dimension (vocab) (9 / 17 / 33, default 17): the resolution–data trade. More bins mean finer actions (a bin centre is off by at most half a bin) but fewer samples per bin and a wider softmax — the tokenizer's vocab-size trade-off in miniature.
  • Transformer width d_model (16 / 32 / 64, default 32): the AR head only — embedding, blocks and head all scale with it. This 2-token problem is easy at 16; the knob is for watching capacity, not for fixing failures.
  • Seed: each head gets a fresh derived init and data stream.
  • Eval seed / Samples across the c grid (4000): the evaluation grid and its sampling noise.
  • Sampling temperature (0–2, default 1.0): 0 means argmax — deterministic decoding, which kills the multimodality (every draw picks the same pair, and the sample scatter collapses to single points). Values at or below 0.01 decode as argmax; higher values mix more, and past 1 they start leaking probability into bins the data never used.

Task 1 (bc-mse) showed the collapse; task 2 (flow) fixed it by keeping the action continuous and sampling a learned flow; this task fixes the same multimodality problem with discrete tokens instead — two different answers to one question, both alive in production VLAs: task 10 (ta-vla) and pi0 / SmolVLA on the continuous side, RT-2 and FAST on the token side.
